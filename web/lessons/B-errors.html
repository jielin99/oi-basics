附录 B：常见编译错误与调试方法

遇到报错不要慌，先看第一条错误（后面的经常是第一条引起的连锁反应），看它报在哪一行、说了什么。

1. 怎么读编译错误

g++ 报错的格式：

文件名:行号:列号: error: 错误描述

例如：

a.cpp:6:5: error: expected ';' before 'return'

意思是：第 6 行第 5 列，在 return 前面缺了一个 ;。注意：缺分号的其实是第 5 行，编译器读到第 6 行才发现。

🎯 警告（warning）也要重视！ 编译时加 -Wall，很多逻辑错误编译器会用警告提醒你。

4. 调试方法

方法 1：输出中间变量（最常用）

for (int i = 1; i <= n; i++) {
    sum += a[i];
    cerr << "i=" << i << " sum=" << sum << "\n";   // 用 cerr 输出调试信息
}

用 cerr 而不是 cout 的好处：cerr 不会写进 freopen 的输出文件，洛谷等 OJ 一般也只检查标准输出，不会因此判错。但输出很多时会拖慢程序，提交前仍然要删掉。

方法 2：手动模拟

拿一组很小的数据（比如 n=3），在纸上一步步模拟程序，把每个变量的值列成表格。这也是初赛“阅读程序”题的标准做法。

步骤ia[i]sum
初始--0
1155
2238
...

方法 3：二分定位

程序很长、不知道哪里错时：在中间某处输出结果，看那里对不对。对 → 错误多半在后半段；错 → 错误在前半段。不断缩小范围。前提是你能判断中间结果“应该是多少”；而且中间结果对，只说明这组数据走到这里没问题，换一组数据可能又不一样。

方法 4：自己造数据

样例通常很弱。提交前自己想几组：

  • 最小：n = 1、n = 0（如果允许）
  • 最大：n 取题目上限，看会不会超时、溢出
  • 特殊：全部相同、全部为 0、有负数、已经排好序、倒序

方法 5：对拍（以后学）

写一个“肯定对但很慢”的暴力程序，和你的程序用大量随机数据比较输出。学到算法阶段再掌握。

方法 6：使用调试器（可选）

小熊猫 Dev-C++ / VS Code 都支持“断点 + 单步执行 + 查看变量”。可以在熟悉基础后学一下，但比赛中最可靠的还是输出调试。

5. 建立你自己的错题本

每次 WA / RE / 卡了很久的题，记录下来：

题号：P1307 数字反转
错误：负数没处理，输入 -380 输出了 0（应该是 -83）
原因：while (n > 0) 对负数一次都不执行
正确做法：先记录符号，转成正数处理，最后加回负号；或者 while (n != 0)
教训：遇到整数题，测一下负数和 0

比赛前翻一翻错题本，比再刷十道新题更有用。
