## 2. 技术规范

- 纯静态 HTML + 原生 JS + CSS，学生端零依赖零构建；`file://` 双击可用，不使用 `fetch`
- 轨迹数据放 `web/data/traces/*.js`，挂到全局 `window.TRACES`，避免 `file://` 限制
- 动画为**人工编排的单步轨迹**，C++ 源码仅用于展示与开发期校验
- 溢出、越界属"无保证行为"：只做示意并标注"由课件检查，C++ 不会自动拦截"，不演示"回绕"
- 开发期依赖：g++（`-std=c++11`）、Node 或 Python3

### 2.1 轨迹数据格式

```js
TRACES["ex-07-01"] = {
  title: "数组下标访问",
  source: "int a[3] = {5,7,9};\ncout << a[1];\n",   // 完整可编译片段见 harness 字段
  harness: "#include <iostream>\nusing namespace std;\nint main(){\n%SRC%\nreturn 0;}\n",
  input: "",                       // 标准输入
  expectOutput: "7",               // verify-traces 比对（去行尾空白）
  kind: "normal",                  // normal | illustrative（溢出/越界/地址类，不比对输出）
  steps: [
    // state = 执行 line 这一行【之后】的状态
    { line: 1, vars: {}, arrays: { a: [5,7,9] }, out: "", note: "a 有 3 个格子，下标 0、1、2" },
    { line: 2, vars: {}, arrays: { a: [5,7,9] }, hl: { a: 1 }, out: "7", note: "a[1] 是第 2 个格子" }
  ]
};
```

约定：一行含多个动作（for 的初始化/判断/更新）按"判断 / 循环体 / 更新"拆步；`line` 从 1 起，必须落在 `source` 行数内；大整数用字符串。

### 2.2 verify-traces（`web/tools/verify-traces.py`）

1. 取 `harness` 替换 `%SRC%`，`g++ -std=c++11` 编译，带 `input` 运行（超时 5s，退出码须为 0）
2. `kind=normal`：输出与 `expectOutput` 比对（统一换行，忽略行尾空白）；`illustrative`：只检查可编译
3. 结构检查：`steps` 非空、`line` 在范围内、最后一步 `out` 等于 `expectOutput`
4. **中间状态不由脚本保证**：每个例子须人工逐步核对，并在 Task 记录中写明

**`fact(3)` 纸面走查结论**：现有格式只有一层 `vars`，不足以表达递归中的"同名 `n`、暂停位置、返回值"。需要给步骤加**可选**字段 `stack`（调用帧数组，栈底在前）：
```js
// fact(3) 其中一步：已递归到 fact(1)，尚未返回
{ line: 3, stack: [ {fn:"fact", vars:{n:3}, at:"等待 fact(2)"},
                    {fn:"fact", vars:{n:2}, at:"等待 fact(1)"},
                    {fn:"fact", vars:{n:1}, at:"执行中"} ],
  ret: null, note: "..." }
// 返回时：栈顶帧弹出，ret 记录返回值，下一帧 at 变为"拿到 1，计算 2*1"
```
无 `stack` 的步骤行为不变，因此对现有格式向后兼容。该字段和 CallStackViz 在第 9 课再实现，本阶段不做。
